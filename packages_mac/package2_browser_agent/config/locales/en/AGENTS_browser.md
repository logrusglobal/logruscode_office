# Website rules

- Tasks that involve working on websites in a real browser (opening pages, clicking, filling in forms, collecting contacts and documents, checking the console/network) must be delegated to the `@browser` subagent via the Task tool. Do not try to automate the browser with bash/curl/webfetch commands when real interaction with a website is required.
- You do not need to start the browser yourself, and you should not ask the user to. The `@browser` agent runs `ensure-browser.command` on its own before its first browser action: if the debugging Chrome is already running it changes nothing, otherwise it starts it and waits until it is ready. The "Browser for OpenCode" file on the Desktop (a copy of `start-browser.command`, double-clickable) remains available as a manual fallback — mention it only if the browser agent reports that it could not start Chrome.
- The `@browser` agent works through the `chrome-devtools` MCP server connected to Chrome on debugging port 9222.
- The `@browser` agent is pinned to an explicit `model` line in its `agents` file, written by the installer from the `model` in `opencode.json`. A subagent with no `model` line does not inherit the caller's model: OpenCode falls back to its own default, which lands on the free tier and fails to start with "OpenCode's free tier can only be used from within OpenCode". If you change the model in `opencode.json`, re-run the installer for package 2 so the two stay in step.
